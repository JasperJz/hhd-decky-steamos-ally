# X11 桌面键盘修复验证（2026-10-17）

问题：HHD 正确识别上划并执行 `steam://open/keyboard`，但桌面模式游戏处于前台时没有可见键盘。绕过 HHD 调用 Steam 也失败，组合键测试同样失败。

实际验证：

- 同一次触摸的代码回放只生成一个手势事件，未复现重复触发。
- 切到 KDE 桌面后，同一 Steam 命令生成键盘窗口；键盘页面本身能够渲染。
- 原始堆叠顺序中键盘位于游戏及登录对话框之下。
- 临时恢复合成并把键盘关联到登录对话框后，桌面截图可见键盘，用户确认触控响应。
- 实现按需兼容助手，测试两轮创建/关闭，退出码正常；不会把短暂的窗口重新挂载当成关闭。
- 安装到 HHD 并重启后台后，用户实际从底部上划，确认键盘弹出且连续点击 Shift/Caps 正常。
- 活跃助手只存在一个实例；3 秒采样约 7.2MiB PSS，CPU 为采样分辨率下的单核 0.0%。这不是帧率基准，也不能证明绝对零开销。
- HHD 正常运行，InputPlumber 继续停止，没有改变输入服务的接管关系。
- 11 项 Python 测试、100 个前端回调与分类重新挂载回归通过。

实现为可选 HHD 核心补丁，旧 Release ZIP 不包含它。只在桌面打开键盘时启动辅助进程，游戏模式走原始调用路径。需要 KDE 默认快捷键、X11、xdotool 和 gdbus。调用期间可能短暂露出桌面；其他桌面、Steam 版本及游戏未穷尽验证。

未读取或记录账号、密码、输入字段或输入内容。现场截图、具体窗口 ID、设备地址及调试脚本没有加入仓库。源文件备份保留在设备 `/var/lib/hhd-trial/desktop-keyboard-plugin-original.py`。
